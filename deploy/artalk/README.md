# Artalk comments

The blog uses the Artalk 2.10.0 client, bundled locally by Hugo. The backend is pinned to the same version. Production comment UI remains hidden until `params.page.comment.artalk.server` is configured. The `artalk-preview` environment connects only to the local service and uses a separate site and database.

## Local preview

Docker must be running. From the blog checkout:

```sh
npm ci
npm run comments:start
npm run preview:comments
```

Open `http://127.0.0.1:1317` and enter an article. Select text within a paragraph, choose **Reply with quote**, and post a comment. The quote and **View context** link are saved as ordinary Markdown inside the Artalk comment. The same Artalk instance moves between the article footer and the discussion panel, preserving drafts and replies. Mobile uses a bottom panel; Escape or the close button returns to the article.

Local data and the generated application key are stored in the ignored `.local-artalk/` directory. These comments never enter the production database. Local captcha is disabled for testing; the production configuration retains Artalk's defaults. Mail notifications require SMTP configuration and are not active in the local preview.

```sh
npm run comments:stop
```

This stops the service and preserves local comments. Stop Hugo with Ctrl+C.

## Production deployment

Use a server with Docker Compose and a domain pointing to its public IP. `comments.omagiclee.com` is a proposed subdomain, not an already-deployed service. Keep ports 80 and 443 available for Caddy's HTTPS certificate and reverse proxy.

1. Copy this directory to the server. Copy `.env.example` to `.env` and set `ARTALK_DOMAIN` to the actual domain. Set `ARTALK_APP_KEY` to a value generated by `openssl rand -hex 32`; keep `.env` private.
2. Start the services from this directory:

   ```sh
   docker compose up -d
   docker compose exec artalk artalk admin
   ```

   The second command creates an administrator interactively; do not put a password in shell arguments. Artalk data and Caddy certificates persist in Docker volumes. The Artalk port is reachable only from the internal Compose network.

3. In the Artalk control center, configure SMTP for reply notifications and review moderation/captcha settings. Frontend and backend site names must both remain `Naifan Li's Blog`. Trusted origins are restricted to `https://blog.omagiclee.com`; add any other real blog origin explicitly if needed. Do not add preview origins to production.
4. Set the blog's `params.page.comment.artalk.server` in `hugo.toml` to the actual HTTPS endpoint, for example `https://comments.omagiclee.com`. Build and deploy the blog through its existing GitHub Pages workflow. GitHub Pages hosts the blog frontend; it cannot run the Artalk server.

The client is an npm dependency, so `npm ci` must precede Hugo builds. Existing posts use their canonical path as the Artalk page key. Preserve published paths, or migrate comment page keys when relocating articles.

## Context links and accessibility

Passage IDs are derived from paragraph text. Context links include the quoted text and nearest section heading as fallbacks. Editing a paragraph can invalidate an exact match; the link then searches for the quote and finally returns to the original section. This provides contextual comments, not permanent document-version annotations. There is one thread per article, with quotes inside individual comments.

The selection toolbar supports plain text paragraphs, headings and lists; code blocks, tables and interactive figures are excluded. Native copying is preserved. Discussion panels use native dialogs, including keyboard focus handling and Escape to close. Artalk verification/notification layers are moved inside the open dialog so they remain accessible.

## Validation

With the local service running:

```sh
hugo --environment artalk-preview --destination /tmp/blog-artalk-preview --buildDrafts=false --cleanDestinationDir
npm run test:comments -- /tmp/blog-artalk-preview
```

The browser check uses an isolated headless browser, writes a clearly identified test comment to the local backend, checks persistence and contextual navigation, and captures screenshots. It never writes to the production endpoint.

Back up the Artalk database/volume before upgrades. To upgrade, update both the exact npm version and the Compose image, validate locally, and deploy the matching versions together. Caddy uses its official `2-alpine` channel.

References: [Artalk documentation](https://artalk.js.org/), [Caddy reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
