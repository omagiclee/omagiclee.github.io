# 实境 · Room Studio

一个在 Mac 本机运行的实景商品预览原型：从手机视频还原真实房间的视觉空间，再放入保留原材质、可按实际尺寸校准的商品模型。主路线为 COLMAP + Brush 3D Gaussian Splatting（3DGS），辅以商品的 glTF/GLB 网格。生成式补全没有作为真实数据加入当前流程。

## 启动

此电脑上的依赖和语音模型已准备好。在 Finder 中双击 `启动实境.command`，或在终端运行：

```sh
cd /Users/omagiclee/Desktop/omagiclee.github.io/local/room-studio
npm start
```

打开 <http://127.0.0.1:4178>。关闭服务可在终端按 Ctrl+C。端口冲突时可使用 `ROOM_STUDIO_PORT=4180 npm start`。

首次安装到另一台 Apple Silicon Mac：需要 Node.js、Python 3.11–3.14、FFmpeg、whisper.cpp；备用照片重建需要 Xcode 及命令行工具。安装基础工具后执行 `npm install`、`npm run setup` 和 `npm run setup:gsplat`。Brush 下载会核对官方 SHA256。设置阶段需要联网；正常运行不会上传视频或录音，也不需要云端账号。图形能力在受限沙箱内可能不可用，应从普通本机终端启动。

## 第一版可以做什么

- 默认显示等待视频导入的实景工作台，不生成替代房间。
- 导入 10 秒到 3 分钟、最大 600 MB 的房间视频；FFmpeg 提取最多 140 帧，COLMAP 在 CPU 恢复相机轨迹，Brush 在本机 GPU 训练 3DGS。快速预览为 2,000 步，细化训练为 8,000 步，训练画面上限 1,000 像素，最多 400,000 个高斯，适配 16 GB 内存机器。质量档位不构成照片级效果保证。
- 备用实验路线由苹果原生 `PhotogrammetrySession` 重建为带纹理的 OBJ 模型；主路线使用 Spark 显示真实的 Gaussian 数据。
- 查看真实生成的模型、处理进度和失败信息，重新打开已有模型；失败时不会用示例房间冒充重建结果。
- 在实景表面选两点，根据已知实际长度校准比例；选三点对齐地面。辅助布局的尺寸和扫描整体朝向也可手动调整。
- 导入自包含 GLB 商品模型，保留纹理、几何和 PBR 材质；支持本机 Draco、KTX2、Meshopt 解码。拒绝引用外部纹理或缓冲文件的 GLB，避免导入后联网取资源。
- 根据商品实际宽度等比例缩放全部轴，设置离地高度，点击实景表面放置；商品模型和位置可保存后恢复。GLB 格式默认使用米，但模型来源的真实尺寸仍需核对。
- 添加沙发、桌子、椅子、床、书架、绿植；选择、移动、旋转、改颜色、复制、删除，检查是否超出房间边界。
- 使用本机 Whisper small Q5 模型识别中文录音，执行受支持的具体设计操作，也可直接输入文字。
- 全景、俯视、WASD 漫游；撤销与重做；本机保存、JSON 导入导出、PNG 画面导出、GLB 设计模型导出。

试试这些指令：

```text
添加一张桌子
把沙发向左移动半米
桌子向前挪二十厘米
把椅子旋转九十度
把沙发改成绿色
墙面改成米白色
地板换成深色木纹
删除选中的家具
撤销
进入房间
保存方案
```

左右前后沿房间坐标解释。有多件同类家具时，先选中目标。不支持的开放式指令会明确提示，尚未接入自由对话式设计模型。

## 实景与布局的边界

视频实景是原始 Gaussian 外观或带纹理扫描，新添加的商品模型与实景一起渲染。3DGS 表示已观察到的纹理与拍摄时的光照，不是可任意重新打光的完整物理场景。扫描中的原有家具仍属于整体模型，目前不能自动识别、单独移动或删除。

商品模型使用独立的物理材质灯光，可手动调整方向和强度。地面校准后可启用近似接触阴影。Gaussian 与网格使用深度测试混合显示，薄表面、透明物体与扫描缺面仍可能造成遮挡误差；当前没有完整的碰撞网格或逆渲染光照恢复。不能把这些近似结果当成已验证的物理真实性。

合成编辑场景只能通过“编辑功能演示”明确进入。基础占位物体也明确标注为非真实商品，商品预览保留导入的原始材质。辅助布局不作为实景外观；在实景中输入墙面改色不会自动切换到合成房间。商品照片不能直接变成尺寸准确的商品模型。

普通 RGB 视频无法提供可信的工程尺寸，需要已知长度校准。未拍到的面、镜子、玻璃、移动物体、反光与模糊可能降低重建质量。第一版不承诺任意视频都能成功或达到近 1:1 外观。真正的用户房间质量必须用用户提供的视频逐个验证，观察留出视角的还原误差与新增物体的遮挡、比例和阴影。备用原生照片重建更偏向物体扫描。

## 拍摄

建议先拍一个光线稳定的房间，45–90 秒。沿房间缓慢移动，让相邻画面充分重叠，包含墙角、地板、家具边缘与侧面。避免镜面特写、人物走动、运动模糊、光照突变；只站在一个点转动手机通常不足以恢复可靠的深度。另记录一段已知的实际长度用于比例校准。

## 数据与验证

数据保存在项目的 `.data/`，语音模型在 `.models/`。这些路径以及编译产物和测试输出已在本项目的 `.gitignore` 排除。录音只用于本机转写，处理完自动删除。服务只绑定 `127.0.0.1`，拒绝其他站点发起的写请求。

```sh
npm test
npm run test:browser
node scripts/reconstruction-smoke.mjs
```

浏览器检查使用博客项目已有的 Playwright 和独立的 headless Chrome for Testing，不操作个人浏览器。原生重建检查使用一个程序生成的带纹理物体视频，验证真实的抽帧和模型生成链路；它不是用户房间，也不能证明真实室内的重建效果。

本机验证已恢复合成视频全部 60 个相机视角（平均重投影误差约 0.48 像素），完成 2,000 步 Brush 训练并生成 4,753 个高斯的 PLY；真实的训练结果在网页查看器中与带嵌入纹理的 GLB 一起加载，商品宽度、离地高度、文字指令和保存恢复已通过测试。这些结果证明链路可运行，测试素材并非真实房间，不证明用户房间的视觉质量。
