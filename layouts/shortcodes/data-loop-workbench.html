GT 审阅

证据来源 → 使用条件

GT 的可信度来自生成与核验过程。教师预测不自动成为真值；以下是证据检查设计，不是准确率测量。

直接观测
传感器与可验证结果

例如关节读数、工具返回、任务完成记录。

查看可信度检查

核对时间戳、标定、完整性与观测边界。传感器值可能有噪声；任务返回成功也需要检查真实结果。

使用条件：来源可追溯，误差与不可观测状态有明确记录。

人工审阅
规范、审核与争议仲裁

例如可见对象标签、偏好判断、失败分类。

查看可信度检查

核对标注规范、审核记录与独立金标准；记录歧义。多人一致不能单独证明正确。

使用条件：明确审核流程，保留争议与标签版本。

模型伪标签
教师预测与约束校验

例如分割、跟踪、描述或动作阶段预测。

查看可信度检查

保存教师版本，检查域差异、校准与独立审核。同一模型生成和验证可能共享偏差。

使用条件：标明伪标签；按任务风险决定复核、降权或隔离。

仿真真值
模拟器内部状态

例如对象位姿、接触、深度与场景语义。

查看可信度检查

真值对应模拟器中的世界；检查物理假设、资产、渲染及真实域差距。

使用条件：记录仿真配置与版本，并通过真实任务验证用途。

发布前检查

样本来源 → 标签证据 → 独立核验 → 歧义/误差记录 → GT 版本。未经核验的标签保持待审状态，不用置信度数字替代审核证据。

迭代复盘

版本绑定 → 决策 → 下一轮

以下以机器人抓取为设计案例。版本号表示演示关联；没有运行实验，不呈现收益数字。

第一轮 · 建立基线
  1. 问题与假设需要确认抓取策略在不同物体上的失败类型。
  2. 数据任务收集成功与失败 episode，校验视频、状态与动作同步。
  3. 版本绑定D1 数据 / G1 标签 / P1 配方 / M1 模型 / E1 评测共同绑定到演示实验 X1；冻结评测划分。
  4. 决策与下一轮若发现接触后滑落，先排除标定与执行异常，再建立补采和 GT 审阅任务；效果仍待验证。
第二轮 · 处理滑落问题
  1. 问题与假设接触阶段数据不足可能是滑落原因；这是假设，需对照验证。
  2. 数据任务关联检索滑落片段与成功对照，补采干预恢复轨迹；审查力觉与动作对齐。
  3. 版本绑定D2 数据 / G2 标签 / P2 配方 / M2 模型 / E1+E2 评测绑定演示实验 X2；沿用冻结 E1，并追加独立分桶 E2。
  4. 决策与下一轮对照基线并检查旧任务回归。只有真实任务复验支持改进才进入发布判断，否则回到归因或数据任务。
第三轮 · 检查迁移与回归
  1. 问题与假设新增物体与环境可能引入分布变化，需要识别适用边界。
  2. 数据任务采集新环境对照，按 episode 与环境隔离评测；审查旧标签与新场景定义是否一致。
  3. 版本绑定D3 数据 / G3 标签 / P3 配方 / M3 模型 / E1+E2+E3 评测绑定演示实验 X3；保留历史版本与回归分桶。
  4. 决策与下一轮结合独立评测、实机复验和回归检查决定继续补采、改配方或回滚。记录证据，再生成下一轮任务。
闭环的结束条件

任务完成不等于问题修复。每一轮需要问题、数据变化、版本链和验证证据，再决定继续、停止或回滚。
