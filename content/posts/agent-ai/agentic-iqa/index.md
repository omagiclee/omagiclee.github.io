一张夜景人像，缩略图看起来明亮、干净，放大后却可能发现眼睛失焦、皮肤被过度平滑，或者发丝边缘出现光晕。反过来，背景中的模糊也可能正是摄影者想要的景深效果。

画质评价的难点因此不只是“这张图应该得几分”，还包括：**哪里值得仔细看？需要取得什么证据？看完局部以后，原来的判断是否应该改变？**

Agentic IQA 关注的就是这段观察过程：模型根据任务和已有证据，选择下一步动作，再利用新取得的信息完成评价。对于影像研发，它有机会把一个总分展开为可定位、可复查的问题，帮助人判断算法究竟改善了什么，又牺牲了什么。

> **资料核验至 2026 年 10 月 23 日。** 本文把 **Agentic IQA** 用作一类方法的统称，把 **AgenticIQA** 专指同名论文。研究基线为 AgenticIQA v2、Q-Probe v6、PACE v1；表中实验来自作者报告，本文未复现模型。文中的人像案例和落地流程是解释性示例与工程建议。

## 1 “主动”意味着评价过程会改变

判断一个系统是否具有主动观察能力，可以问一个具体问题：**前一步发现的疑点，会不会改变下一步看到的图像区域、调用的工具，或检查的问题？**

{{< codex-table label="四种画质评价流程的区别" >}}
| 流程 | 输入如何被观察 | 能回答什么 |
| --- | --- | --- |
| 固定评分器 | 通过既定预处理与模型计算 | 在定义好的尺度上给分 |
| 固定多尺度／多裁剪 | 按预设位置、尺寸取样再聚合 | 扩大细节覆盖范围 |
| 单次 VLM 评价 | 根据本次输入生成分析与答案 | 解释可见的画质现象 |
| 主动评价 | 根据疑点选择动作，取得新证据后更新判断 | 解释看了哪里、为何追加检查、结论依据是什么 |
{{< /codex-table >}}

这个表按**推理时的工作方式**分类，不是模型能力排行榜。固定多尺度模型也可能非常准确；单个 VLM 也可以承担整个观察闭环。模型数量、回答长度和工具数量，都不能单独证明“主动”带来了价值。

下面是本文归纳的通用流程，并非某篇论文的逐模块复刻：

{{< mermaid >}}

这里的 IQA 是 Image Quality Assessment，图像质量评价。**无参考评价（NR-IQA）**没有可用的高质量参考图；**全参考评价（FR-IQA）**依赖参考图。Agent 可以选择工具，但不能凭空创造一张可信参考。对生成式修复而言，结果更清晰和结果忠实于原始内容，也需要分别检查。

## 2 研究路线：打分、推理、取证与定义标准

这些工作解决的问题不同，更适合放在一张能力地图中理解。

{{< codex-table label="从视觉评分到主动画质评价的代表性研究" >}}
| 研究 | 主要切入点 | 与主动观察的关系 |
| --- | --- | --- |
| [Q-Align，2023](https://arxiv.org/abs/2312.17090v1) | 用文字定义的质量等级训练视觉评分 | 建立评分能力；不以动态取证为核心 |
| [Q-Insight，2025](https://arxiv.org/abs/2503.22679v2) | 用 GRPO 联合优化评分与退化感知 | 让质量推理受到任务奖励约束 |
| [AgenticIQA，2025](https://arxiv.org/html/2509.26006v2) | 按用户问题组织分析和 IQA 工具 | 决定调用什么、怎样汇总证据 |
| [Q-Probe，2026](https://arxiv.org/html/2601.15356v6) | 面向高分辨率图像学习上下文相关的裁剪 | 决定看哪里，并将局部放回全局解释 |
| [PACE，2026](https://arxiv.org/html/2609.22942v1) | 为新的感知维度构造可核查的评价协议 | 决定一个抽象要求应被拆成哪些视觉问题 |
{{< /codex-table >}}

沿着这张地图看，影像团队可以分别讨论三种能力：**取得证据的能力、判断证据的能力、定义评价目标的能力**。例如，把“皮肤自然”拆成可观察的问题，与找到皮肤所在区域，并不是同一个学习目标。

## 3 AgenticIQA：让工具调用服从问题

AgenticIQA 将工作划分为 Planner、Executor、Summarizer 三个角色，并可共用一个 VLM 底座。Planner 确定问题范围与所需步骤；Executor 完成失真识别、分析、工具选择和执行；Summarizer 汇总结果，证据不足时要求重新规划。其 AgenticIQA-200K 数据用于训练这些角色。[论文 §3](https://arxiv.org/html/2509.26006v2#S3)

值得注意的是，论文对**全局定量任务**和**局部解释任务**采取不同路径：局部问题不会自动触发全局 IQA 工具打分。因此，不能把这套框架直接理解成“对任意区域反复放大评分”。[Planner 规则](https://arxiv.org/html/2509.26006v2#S3.SS1)

用工程语言理解，可以把问题路由写成下面这张表；这是本文的应用示例：

{{< codex-table label="根据用户问题选择评价路径的示例" >}}
| 用户真正想知道什么 | 应先明确什么 | 合适的输出 |
| --- | --- | --- |
| 这批压缩图片总体怎样 | 是否有同内容、已配准的参考图 | 批量分数、异常样本及评价条件 |
| 这个人的眼睛是否清楚 | 目标人物、查看尺度、原图局部 | 对该区域的观察与证据位置 |
| 降噪版本 A 和 B 谁更好 | 噪声与纹理分别怎样权衡 | 分维度比较、偏好及无法区分项 |
| 为什么这张人像显得不自然 | “不自然”可能涉及的具体维度 | 待核查问题与逐项证据 |
{{< /codex-table >}}

### 实验没有证明它全面胜出

以下只摘录同一论文表 2 的 **SRCC**，即预测排序与人工平均意见分（MOS）排序的相关程度，越高越好。各列有自己的数据与参考条件，不能把数值拼成统一能力排名。

{{< codex-table label="AgenticIQA 论文表 2 的部分 SRCC 结果" >}}
| 方法 | TID2013 | BID | AGIQA-3K |
| --- | ---: | ---: | ---: |
| Q-Align | 0.8313 | **0.8967** | **0.8013** |
| AgenticIQA（Qwen2.5-VL*） | 0.7780 | 0.7771 | 0.7165 |
| AgenticIQA（GPT-4o） | **0.9165** | 0.8889 | 0.7937 |
{{< /codex-table >}}

星号表示论文微调后的底座。GPT-4o 版本在这三行的 TID2013 比较中领先，但另外两列仍低于 Q-Align；Qwen 版本则三列均低于 Q-Align。另一个解释性问答测试 LLVisionQA 中，GPT-4o 接入框架后的总体准确率由 77.88% 变为 77.95%，只增加 **0.07 个百分点**。[原文表 2、表 3](https://arxiv.org/html/2509.26006v2#S5)

我的判断是，这些结果支持继续研究任务适配和证据组织，但采购或部署决策仍需回答：增加调用成本以后，在自己的图像上少错了哪些问题？

## 4 Q-Probe：放大以后，还要知道自己在看什么

Q-Probe 的重点是高分辨率局部退化。模型可以发出裁剪动作，从原始高分辨率图中取得区域，将裁剪图加入上下文后继续判断；论文推理流程最多进行 6 轮。训练采用 **GRPO → SFT → GRPO**：先对齐质量判断，再学习包含正常区域的观察轨迹，最后用评分与定位等奖励细化行为。[方法与推理附录](https://arxiv.org/html/2601.15356v6#S3)

它指出一个关键偏差：如果训练中每次裁剪都对应缺陷，模型可能学成“被放大的区域就有问题”。自然景深也容易在脱离全局时被当作退化。[问题分析](https://arxiv.org/html/2601.15356v6#S1)

### 哪些观察数据有用

下面是作者在 Vista-Bench 上的裁剪策略消融。PLCC 表示预测分与人工分的线性相关程度；这里沿用论文协议，不跨论文比较。

{{< codex-table label="Q-Probe 论文表 4 的裁剪策略消融" >}}
| 裁剪覆盖策略 | SRCC ↑ | PLCC ↑ |
| --- | ---: | ---: |
| 只覆盖退化区域 | 0.578 | 0.650 |
| 部分退化 + 部分正常区域 | 0.767 | 0.819 |
| 全部退化 + 部分正常区域 | **0.801** | **0.850** |
{{< /codex-table >}}

来源：[Q-Probe v6，表 4](https://arxiv.org/html/2601.15356v6#S4.T4)。Vista-Bench 由高分辨率图像局部合成退化并经人工评价构建；这是特定基准上的结果，不能直接外推到真实手机 ISP 的全部问题。

从实验设计角度看，这组消融比单看最终分数更有启发：**观察训练应包含“检查后排除缺陷”的路径。** 在业务数据里，可以有意识地收集容易被误报的正常样本，并记录模型究竟在哪一步改变了判断。

## 5 用一张人像，把观察过程展开

假设要比较同一张夜景人像经过两套降噪算法后的结果。目标是“人物清楚、皮肤自然、背景噪声可接受”。以下为示意任务，没有对应的模型实测分数。

{{< codex-table label="夜景人像的主动画质检查示例" >}}
| 当前疑点 | 下一步观察 | 什么证据会改变判断 |
| --- | --- | --- |
| A 看起来更干净，是否抹掉了纹理 | 在相同显示尺度比较面颊、额头与衣料 | 颗粒减少的同时，毛孔和织物结构是否一起消失 |
| B 的眼睛似乎更锐利 | 核查睫毛和眼睑边缘，同时看邻近皮肤 | 更清楚的结构，还是额外产生的亮边与暗边 |
| 背景模糊是否需要扣分 | 回看焦点主体、前后景关系和边缘过渡 | 是否与拍摄意图、空间关系和主体清晰度一致 |
| 一小块问题是否影响整体 | 在目标输出尺寸重新查看全图 | 局部问题是否仍可见，是否位于主要关注区域 |
{{< /codex-table >}}

这条路径的价值，是把几个原本混在一起的结论拆开了：A 可能在背景降噪上更好，B 可能保留更多肤质，但两者在正常观看尺寸下未必有稳定的总体偏好。

一个有用的报告可以这样表达：

> A 的背景颗粒更少；在同尺度的面颊局部，B 保留了更多细小纹理。A 是否存在过度平滑，还需要结合输入图和人工盲评确认。当前证据不足以给出稳定的总体胜者。

这里应保存的是**可复查的观察结果**：图像版本、区域坐标、显示尺度、工具输出、比较条件。模型生成的长篇解释本身，并不能证明它确实利用了这些证据。

<details>
<summary>展开：为什么“放大”也需要固定观察条件</summary>

对同一张图，不同预处理可能改变人和模型看到的现象。作为实验设计，至少应固定下面几项：

| 条件 | 本文建议 |
| --- | --- |
| 裁剪来源 | 从原始文件提取局部，保留原始宽高与坐标映射 |
| 缩放方式 | 记录缩放比例与插值方式；区分原生像素查看和目标观看尺寸 |
| A/B 对照 | 对应同一内容、同一位置与同一尺度；必要时先配准 |
| 全局上下文 | 保留全图及区域位置，避免将局部现象直接推广到整图 |
| 色彩与动态范围 | 固定解码、色彩转换和 HDR 到 SDR 的处理；结论限定到实际送入模型的图像 |
| 生成式增强 | 若用于辅助查看，应另存派生版本；新增细节不能充当原图已有细节的证据 |

“局部看着更差”和“产品最终呈现更差”可能对应不同的观察尺度。评价报告应该说明自己回答的是哪一个问题。

</details>

## 6 PACE：新维度需要先定义怎样观察

主动裁剪解决了“看哪里”，但“肤质自然”“文字可信”“光影合理”仍不是可以直接交给一个通用总分的任务。

2026 年 9 月的 PACE 提出构造评价协议：将目标维度拆成可核查的视觉问答，由多个角色生成和审查，再结合绝对判断与参考锚点进行评分。其开放维度流程使用每个维度 4 张人工评分图做校准；不更新模型参数，并不等于不需要人工信息。论文基准实验则从训练划分选取高低分锚点，与测试划分分离。[PACE 方法及实验设置](https://arxiv.org/html/2609.22942v1#S4)

以下是借鉴这个思路、面向人像算法设计的示例协议，**不是 PACE 原论文的实验配置**：

{{< codex-table label="把肤质自然转为可核查问题的示例" >}}
| 评价维度 | 可观察的问题 | 需要保留的限制 |
| --- | --- | --- |
| 纹理保持 | 皮肤局部是否出现大块均匀、蜡状区域 | 妆容、光照和输入本身也影响纹理 |
| 局部连续性 | 面颊、鼻翼和颈部的质感是否突然断裂 | 正常肤质差异不能直接算算法缺陷 |
| 边缘处理 | 发丝、眼镜和脸部轮廓是否出现光晕或粘连 | 需要原图局部及相同尺度对照 |
| 内容忠实性 | 修复是否改变可确认的细节 | 没有可信参考时，应保留不确定性 |
{{< /codex-table >}}

我更看重这种路线对评价标准的显式化：人可以审核每个问题是否合理、是否重复、是否真的可见。对一个新维度，先把协议讨论清楚，再收集评分，通常比直接讨论“总分应该是多少”更容易定位分歧。

## 7 真正落地，要测的是观察有没有贡献

在自己的数据上验证时，我会先固定底座模型与输入预算，构建四个可比较的系统。下面是建议的实验方案，不是上述论文已经完成的实验。

{{< codex-table label="验证主动观察贡献的四组对照实验" >}}
| 对照组 | 工作方式 | 用来回答的问题 |
| --- | --- | --- |
| A：直接评价 | 只提供全图与固定问题 | 基础能力到哪里 |
| B：固定取样 | 增加预设局部，限定相同数量／像素预算 | 多看到像素本身能带来多少收益 |
| C：主动取样 | 模型决定是否查看、查看哪里 | 自适应选择是否优于固定覆盖 |
| D：主动取样 + 工具 | 在 C 上增加适用的量化结果 | 专业工具提供了多少独立信息 |
{{< /codex-table >}}

应该同时报告固定预算下的质量，以及达到相近质量所需的成本。如果 C 比 A 更好，却不如相同预算的 B，那么当前收益主要来自额外观察，还没有证明动作选择有效。

### 五类指标一起看

{{< codex-table label="主动画质评价的验收维度" >}}
| 维度 | 建议记录 | 防止遗漏什么 |
| --- | --- | --- |
| 最终判断 | SRCC、PLCC、A/B 偏好一致率、按场景分组结果 | 平均相关性掩盖具体场景退步 |
| 缺陷发现 | 误报率、漏报率；有框标注时的定位表现 | 只会描述常见问题，漏掉关键局部 |
| 正常效果保护 | 正常景深、运动表现、颗粒风格等困难负样本的误罚 | 把任务允许的效果当作缺陷 |
| 证据有效性 | 区域是否相关、工具是否适用、替换证据后结论是否合理变化 | 答案看似正确，实际忽略新增证据 |
| 资源与稳定性 | 延迟分位数、输入像素／token、调用次数、重复评价分歧 | 少数困难样本的长尾成本 |
{{< /codex-table >}}

对证据有效性，可以做受控干预：保持任务不变，将缺陷区域替换成对应正常区域，观察局部判断是否随之改变；再替换一个无关区域，检查结论是否过度波动。应构造视觉上连贯的对照样本，避免拼接痕迹成为新的捷径。这类实验检验的是新增观察对答案的贡献。

### 评分工具也有自己的契约

IQA-PyTorch 提供 FR、NR 等工具，以及分数方向属性 `lower_better`；其文档也明确区分是否校正 PLCC 等评测口径。[官方使用与评测说明](https://github.com/chaofengc/IQA-PyTorch#advanced-usage-with-codes)

因此，工具注册表至少要描述：需要什么输入、评价什么、分数方向、预处理、模型版本和适用条件。一个模型擅长总体质量预测，不等于它的分数能被解释成“噪声强度”。不同指标的原始分数也不能直接相加平均。

<details>
<summary>展开：数据划分、分数校准与停止条件</summary>

**先按内容划分，再生成派生样本。** 同一张原图的不同压缩版本、裁剪和修复结果，应留在同一划分；同一连拍或视频相邻帧也要考虑关联。否则测试集可能只是在检查模型是否见过相似内容。

**训练、校准和测试承担不同职责。** 分数映射在训练或独立校准数据上拟合，测试时冻结。若论文协议包含利用测试 MOS 做非线性拟合后报告 PLCC，应如实标注，不能把它当成线上可直接使用的分数校准。

**允许没有胜者。** 两个版本差异很小时，可以输出无法稳定区分；模型的自报置信度需要用标注数据验证，不能直接充当正确概率。

**把停止定义为可执行规则。** 可以限制观察轮数、累计像素和总时延；也可以在关键问题均有证据、继续观察不再改变判断时提前停止。达到预算仍存在疑点，应带着未解决项退出，而不是补一个确定结论。

**区分训练奖励与部署信息。** 缺陷框、人工分和优劣标签可以用于训练或评测；部署时若没有这些信息，就不能把依赖它们的判断规则当作可用能力。

</details>

## 8 在影像流程里，先让它帮助发现问题

我的起点会是**离线算法回归与困难样本复核**：任务明确、可以保存原图，也能用人工检查验证观察是否正确。先围绕一种问题建立有效闭环，再逐步扩大维度与场景。

这也可以衔接[影像画质 Auto GT 生成方案]({{< relref "/posts/data-flywheel/image-quality-auto-gt/index.md" >}})：评价器帮助筛选候选、标记异常并给出复核依据。生成模型偏好的结果，仍需要通过独立证据确认；自动评价通过也不会让伪参考自动变成真实 GT。

值得优先研究的问题是：**在相同观察预算下，系统能否更少漏掉主体缺陷、更少误罚正常效果，并把每次判断对应到可复查的图像证据。** 当这三件事在具体业务中成立，“会主动观察”才形成了可交付的价值。

## 参考资料与阅读顺序

1. **工具编排**：[AgenticIQA，v2](https://arxiv.org/html/2509.26006v2)。重点读 §3 的任务路由，以及表 2、表 3 的收益边界。
2. **主动裁剪**：[Q-Probe，v6](https://arxiv.org/html/2601.15356v6)。重点读上下文裁剪、表 4 消融和附录 B 的推理流程。
3. **开放维度**：[PACE，v1](https://arxiv.org/html/2609.22942v1)。重点读协议构造、人工校准及基准实验的锚点来源。
4. **评分与推理背景**：[Q-Align](https://arxiv.org/abs/2312.17090v1)、[Q-Insight，v2](https://arxiv.org/abs/2503.22679v2)。帮助区分质量评分、质量推理与动态观察。
5. **实现工具**：[IQA-PyTorch](https://github.com/chaofengc/IQA-PyTorch)。核对每项指标的输入、分数方向、权重和评测协议。
