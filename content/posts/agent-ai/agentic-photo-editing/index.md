给一张逆光人像，要求“脸亮一点，肤色自然，保留傍晚的感觉”。这句话没有告诉系统曝光加多少、先改白平衡还是曲线，也没有说明怎样判断天空已经过曝、皮肤开始失真。

**Agentic Photo Editing 把这些决策串成一个循环：理解目标、提出操作、调用修图工具、检查结果，再决定下一步。** 对影像画质研究来说，值得关注的是能否把场景理解、参数控制和质量评价接在一起，让系统解释每一步改善了什么、损伤了什么。

PhotoAgent 提供了探索式规划的代表方案。面向自动曝光校正、白平衡和色彩调整，我更看好一个受约束的起点：**让 Agent 提出编辑策略，让明确的图像算子完成渲染，再用独立评价约束结果。**

> 资料核验日期为 **2026 年 10 月 23 日**。PhotoAgent 最新 arXiv 版本为 **v3，2026 年 7 月 16 日**，标题已改为 *Exploratory Visual Aesthetic Planning with Large Vision Models*。默认 `code` 分支 README 仍标注代码、预训练模型和 Demo 待发布；本文讨论公开方法与作者实验，后半部分给出画质方向的实验设计。[论文版本](https://arxiv.org/abs/2602.22809v3)、[官方 README](https://github.com/mdyao/PhotoAgent/blob/code/README.md)

## 1 智能体修图覆盖三类不同问题

“修得更好”至少可以指向三种目标。它们可能共享工具，但成功标准不同。

{{< codex-table label="智能体修图的任务边界" >}}
| 路线 | 典型任务 | 主要判断标准 |
| --- | --- | --- |
| 参数化修图 Retouching | 曝光、白平衡、曲线、饱和度、局部调色 | 达到目标观感，同时保持内容与纹理 |
| 图像复原 Restoration | 降噪、去模糊、去压缩伪影、超分辨率 | 减轻退化，同时控制细节误差和伪影 |
| 语义与创意编辑 | 删除路人、替换背景、添加物体 | 编辑意图达成，指定保留区域不被破坏 |
{{< /codex-table >}}

PhotoAgent 的公开设计包含传统图像工具与生成式编辑器，目标覆盖高层语义编辑。MonetGPT、JarvisArt 更适合观察参数化修图怎样连接自然语言；AgenticIR 则把调度重点放在复原工具及其执行顺序上。[PhotoAgent](https://mdyao.github.io/PhotoAgent/)、[MonetGPT](https://monetgpt.github.io/)、[JarvisArt](https://arxiv.org/abs/2506.17612)、[AgenticIR](https://arxiv.org/abs/2410.17809)

因此，研究开始前应先写清目标：可以改变光影和色调，是否也允许改变场景内容？如果任务只是“纠正曝光”，天空中多出一轮太阳，即使更好看，也已经改变了任务。

这里的**曝光校正**指拍摄后的图像处理。若要进一步研究相机自动曝光 AE，还需要把快门、光圈、增益、运动模糊和实时控制纳入系统；照片后处理实验不能直接证明拍摄控制有效。

## 2 PhotoAgent 怎样把修图组成闭环

PhotoAgent 的核心分工可以用下面这张图理解。记忆保存编辑过程，视觉反馈把已经发生的变化交回下一轮决策。[官方方法说明](https://github.com/mdyao/PhotoAgent/blob/code/README.md)

### 规划要考虑后续操作的影响

MCTS 是蒙特卡洛树搜索。可以把当前图像理解为树的根节点，把候选操作理解为分支；搜索在尝试新路径与继续探索已有好路径之间分配预算，再根据结果更新判断。

放到画质任务中，一个直观例子是：整体提亮能够改善暗脸，但可能压缩后续处理天空的空间；先控制高光、再调整主体，可能得到不同结果。**操作顺序值得搜索，但是否需要树搜索，要由相同预算下的对照实验决定。** 这个例子用于解释规划问题，不是 PhotoAgent 的实测案例。

PhotoAgent 在较低分辨率上模拟候选路径，再对入选动作做实际执行与重评分；实际结果不改善时可以回退。这让规划的估计有机会被真实输出纠正。[论文方法与附录 A](https://arxiv.org/html/2602.22809v3#S3)

对画质研究的启发是：缩略图可用于筛选色调和构图，但最终验收应回到全分辨率，并检查皮肤、发丝、文字和高反差边缘。缩略图上更干净，可能只是细节被平滑掉了。

### 工具与评价器共同决定能力边界

能生成漂亮的编辑建议，不等于能输出合适的参数。系统还需要知道工具如何处理颜色、局部区域和中间结果。

{{< codex-table label="从修图建议到执行结果的三个问题" >}}
| 环节 | 需要回答的问题 | 可能的失败 |
| --- | --- | --- |
| 候选生成 | 看见的问题是什么，目标是什么 | 把暖色氛围误诊为偏色 |
| 工具执行 | 操作作用于哪个区域、使用什么参数 | 提亮整张图，导致天空剪裁 |
| 结果评价 | 改善是否符合目标，细节是否受损 | 整体分升高，但肤色和纹理变差 |
{{< /codex-table >}}

这也是我认为“影像画质 × Agent”有研究价值的原因：成像知识可以落到动作、工具和评价三个位置，而不是只写在一段提示词里。

## 4 相关工作各自补上哪一块

下面按“对画质调优有什么用”比较代表性工作。不同论文使用不同数据与评价方式，表格不构成统一性能排名。

{{< codex-table label="智能体修图与图像复原的代表工作" >}}
| 工作 | 核心机制 | 适合借鉴的部分 |
| --- | --- | --- |
| [PhotoAgent](https://github.com/mdyao/PhotoAgent/blob/code/README.md) | 探索式规划、异构工具、反馈与历史 | 比较候选路径、保留与回退 |
| [MonetGPT](https://monetgpt.github.io/) | 用视觉谜题训练模型理解图像操作；分阶段执行参数化修图 | 让模型理解“参数变化会造成什么视觉变化” |
| [JarvisArt](https://arxiv.org/abs/2506.17612) | 调用 Lightroom 的 200 余种工具；先监督训练，再用 GRPO-R 优化 | 将自然语言目标连接到专业全局与局部调整 |
| [JarvisEvo](https://arxiv.org/abs/2511.23002) | 交错的视觉与文本推理，编辑器和评价器协同优化 | 减少指令幻觉与奖励投机，研究评价器如何跟上策略 |
| [IEA](https://github.com/OpenDFM/Image_Edit_Agent) | Qwen2.5-VL-7B 驱动参数化编辑器，支持 16 种全局工具 | 用较小动作空间研究对话意图、参数预测和可检查轨迹 |
| [AgenticIR](https://arxiv.org/abs/2410.17809) | 感知、调度、执行、反思、重新调度，并积累工具使用经验 | 复合退化诊断、复原模型选择和顺序控制 |
{{< /codex-table >}}

MonetGPT 的阶段分别关注光照、饱和度与白平衡、选择性色彩，每个阶段把中间图像反馈给模型。对曝光和色彩研究，这是一个有用的提醒：**动作空间可以带有摄影领域的结构，不必从任意工具序列开始搜索。**[MonetGPT 方法概览](https://monetgpt.github.io/)

如果现在启动实验，我会优先看 IEA 的工具接口与轨迹，再看 JarvisArt 的局部调整和训练方式；涉及降噪、去模糊组合时，再引入 AgenticIR。IEA 已提供代码和模型入口；JarvisArt README 列出推理、训练、评测与模型入口；AgenticIR 提供探索和推理流程。这些入口便于检查实现，实际复现仍要匹配依赖、数据和算力。[IEA 实现](https://github.com/OpenDFM/Image_Edit_Agent)、[JarvisArt 实现](https://github.com/LYL1015/JarvisArt)、[AgenticIR 实现](https://github.com/Kaiwen-Zhu/AgenticIR)

## 5 评价闭环需要区分画质与审美

“更好看”“更符合指令”“更接近原始内容”“没有新伪影”，是四个可以发生冲突的目标。系统如果只追一个总分，就可能找出讨好评价器的捷径。

例如，增加饱和度可能强化风景的视觉冲击，却使肤色偏橙；降噪可能改善平滑区域，却抹掉衣服纹理。下面是面向保真修图的评价分工建议。

{{< codex-table label="画质修图的四类评价信号" >}}
| 评价维度 | 可以观察什么 | 不宜直接等同于什么 |
| --- | --- | --- |
| 目标达成 | 指定区域的亮度变化、色调方向、指令满足 | 全图越亮越好 |
| 成像质量 | 噪声、边缘光晕、纹理损失、色带与剪裁 | 单个无参考分数代表全部画质 |
| 内容保持 | 几何、身份、文字、局部结构和非目标区域 | 语义相似就代表细节完全一致 |
| 审美与偏好 | 自然度、氛围、肤色接受度、用户选择 | 所有用户都喜欢同一种风格 |
{{< /codex-table >}}

Q-Align 用文字定义的等级训练视觉评分，覆盖图像质量和审美等任务；DepictQA-Wild 则提供质量描述与图像比较。它们分别启发两种接口：**用分数辅助筛选，用具体问题描述指导下一步。** 这些模型在目标设备和场景上的可靠性，仍应通过留出的人工标注校准。[Q-Align](https://arxiv.org/abs/2312.17090)、[DepictQA-Wild](https://arxiv.org/abs/2405.18842v3)

### 搜索越充分越需要检查评价偏差

JarvisEvo 把静态奖励模型下的 reward hacking 列为关键问题，并提出编辑器与评价器的协同优化。它提示我们：评价器会参与塑造策略，不能只在实验结束时充当计分器。[JarvisEvo](https://arxiv.org/abs/2511.23002)

我的实验建议是把职责分开：内环评价器用于选择候选；最终验收使用留出的照片、不同的评价信号和人工盲评。盲评随机交换左右顺序，允许“平局”和“两者都不可接受”，不要强迫评审从两个坏结果里选一个好结果。

对于必须保持的内容，优先设置拒绝条件。例如脸部几何改变、文字损坏或明显边缘光晕，应阻止候选被接受；审美分增加不应把这些损伤抵消掉。阈值需要在开发集校准，并保留分组结果，避免只报告一个平均分。

### 用明确的参数语义连接模型与工具

起步阶段可以只开放曝光、白平衡、色调曲线、饱和度，以及带 mask 的局部曝光。裁剪、对象增删和背景替换放在独立任务中评价，避免把保真修图的收益混在内容改写里。

工具契约至少要说清输入域、单位、范围、作用区域和管线版本。以曝光为例，在线性域用 EV 表示乘法增益，与在编码后的 RGB 上直接加亮度，产生的行为不同。JPEG 中已经剪裁掉的信息，也不能通过降低曝光参数得到真实恢复。

<details>
<summary>展开工具与状态记录建议</summary>

{{< codex-table label="参数化修图工具的契约与状态" >}}
| 记录项 | 目的 |
| --- | --- |
| 原图摘要、解码器与色彩配置 | 确定每次重放从同一份数据开始 |
| 工具名、实现版本、参数单位 | 避免不同编辑器的同名滑块被当成同一种算子 |
| RAW 或 RGB 域、位深与输出变换 | 区分处理域与展示域，控制中间量化损失 |

| 每轮候选、评价、接受或拒绝理由 | 复查为何选择这一条轨迹 |
| 调用次数、耗时、停止原因 | 衡量效率，区分主动停止与预算耗尽 |
{{< /codex-table >}}

如果底层渲染器使用固定顺序，应让 Agent 修改完整参数配方，而不是假设工具调用顺序一定等于像素处理顺序。重放时使用高精度中间表示，避免每轮重新压缩 JPEG。

### 先把一个逆光人像问题做扎实

对开头那张照片，系统可以先生成三个候选：整体曝光微调、仅主体局部提亮、主体提亮并配合高光控制。所有候选与原图一起参加比较。

验收重点是脸部可辨认程度、肤色自然度、天空剪裁与主体边缘，而不是简单提高平均亮度。若背景的暖光是目标氛围，白平衡模块就需要保留它；“看起来暖”本身不足以证明有色偏。这个案例的研究问题是：**场景与目标信息，能否帮助系统选择比通用自动增强更合适的参数？**

局部 mask 也属于误差来源。主体变亮后，发丝和肩部边缘可能暴露分割问题，因此要把边缘检查算入闭环，而不能只评价脸部中心。

## 7 怎样设计能说明问题的实验

最小实验应先回答两个问题：闭环是否比一次预测好；模型规划是否比同预算的简单搜索好。只有这两点成立，再增加更长的搜索、更大的工具集和策略训练。

### 建议从一个小规模分层试验开始

可以先收集约 **300 张照片**，覆盖逆光人像、混合光人像、低光、风景、室内和本身已处理良好的照片。以约 100 张开发、200 张留出测试为起点，按拍摄会话或摄影者分组，避免近重复图跨集合。这个数量用于发现失败模式，不足以独立支持广泛泛化结论。

第一轮预算可设为每图最多 3 轮、每轮 4 个候选，并记录所有工具与评价调用。一次模型调用与一次工具渲染的成本不同，预算应同时报告调用量、实际耗时和显存等资源，而不是只比较“轮数”。

{{< codex-table label="画质智能体的基线与消融设计" >}}
| 对照 | 要回答的问题 |
| --- | --- |
| 原图与固定自动增强 | 系统是否真的改善照片，是否对好图过度处理 |
| 相同工具下的随机或坐标搜索 | 收益来自语言模型的决策，还是多试几个参数 |
| VLM 一次预测配方 | 视觉反馈带来了多少增益 |
| 逐轮评价的贪心策略 | 更复杂的路径规划是否值得额外成本 |
| 有预算的树搜索 | 在相同渲染与评价预算下，前瞻是否有用 |
| 去掉局部检查或停止机制 | 哪些设计减少了损伤与无效编辑 |
{{< /codex-table >}}

**主指标建议用人工成对偏好与不可接受率共同呈现**，附平局比例、置信区间和场景分组。多位评审对同一照片的投票不是独立图像样本，区间估计应考虑照片或拍摄组的聚类。另报内容损伤率、原图保留率、平均调用数与 P95 延迟，避免只挑成功案例展示。

<details>
<summary>展开参考图、色彩与数据划分的注意点</summary>

有配准可靠的目标图时，可以使用像素或感知误差辅助评价；但专家修图属于某种偏好参考，不自动等于唯一正确答案。没有目标参考时，原图可用于内容保持检查，却不适合充当“调整后必须逐像素接近”的唯一质量目标。

色彩误差需要明确参考、色彩空间与观察条件。在色卡或可靠中性参考缺失时，不能仅凭自然照片里的某个物体“应该是白色”，就宣称测到了白平衡真值。显示色彩管理和观看条件也应在盲评中保持一致。

工具学习可以利用可追溯的编辑轨迹；偏好学习可以保留获胜、平局和被拒绝的候选。它们适合的训练用途不同。若进一步生产训练配对，建议沿用[影像画质 Auto GT 方案]({{< relref "/posts/data-flywheel/image-quality-auto-gt/index.md" >}})的来源与审核记录，把工具编辑结果标为伪参考。

</details>

## 8 值得优先验证的研究方向

{{< codex-table label="影像画质与智能体结合的研究问题" >}}
| 方向 | 可检验的假设 | 关键证据 |
| --- | --- | --- |
| 场景与目标驱动的曝光校正 | 区分逆光、夜景和氛围目标，可以减少错误提亮 | 分场景盲评、剪裁与噪声变化 |
| 白平衡与肤色联合控制 | 同时观察主体与环境，比单纯全局纠偏更符合意图 | 不同光源和肤色条件下的接受度 |
| 原图约束下的局部编辑 | 区域约束可以改善主体，同时降低附带损伤 | 主体收益、边缘伪影、非目标区域变化 |
| 预算自适应与主动停止 | 简单图片少搜索，好图直接保留，可以降低平均成本 | 质量与延迟曲线、原图保留率、困难样本退化 |
| 偏好记忆与批量一致性 | 用户纠正可以减少后续同类错误，并稳定一组照片的风格 | 留出会话上的收益，旧场景能力回归 |
{{< /codex-table >}}

其中，我会优先做**有内容保持约束的曝光与肤色调优**。它的动作空间相对可控，也容易把失败归因到诊断、参数、mask 或评价。待这条链路稳定后，再研究更长的规划与个性化学习，能够更清楚地判断新增复杂度带来了什么。

偏好记忆还应区分“这次要暖一点”与“以后都喜欢暖色”。把一次指令当成永久风格，可能让系统越来越偏离用户；经验能否跨会话改善结果，可以接着用[Agent Memory 与持续学习]({{< relref "/posts/agent-ai/agent-memory-continual-learning/index.md" >}})中的验证思路评估。
