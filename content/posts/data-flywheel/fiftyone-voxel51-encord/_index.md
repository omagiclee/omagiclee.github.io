## 产品关系与定位

Voxel51 同时是公司名与商业平台品牌，商业产品旧称 FiftyOne Enterprise。[FiftyOne 官方仓库](https://github.com/voxel51/fiftyone)、[Voxel51 商业文档](https://docs.voxel51.com/enterprise/)

| 观察维度 | FiftyOne 开源版 | Voxel51 商业平台 | Encord |
| --- | --- | --- | --- |
| 产品形态 | Python SDK 与浏览器分析工具 | 可供团队共享的数据平台 | 整合数据管理、标注和评测的平台 |
| 典型使用者 | 算法工程师、研究者、工具开发者 | 算法、项目管理、标注审核、管理员 | 数据与 ML 团队、项目管理、标注审核 |

表中概括各产品的使用方式，具体能力与版本条件见对应文章。

## 阅读时需要区分的概念

| 概念 | 应如何区分 | 混淆后的实际问题 |
| --- | --- | --- |
| 原始文件 / 元数据 | 图片、视频等文件内容，与路径、采集时间、来源等记录分开保存 | 只备份数据库，可能遗漏媒体文件 |
| 筛选条件 / 选中项 | 条件决定哪些数据出现在结果中；选中项决定本次操作处理哪些数据 | 批量动作处理了错误的数据范围 |
| 保存视图 / Collection | 视图保存查询规则；Collection 保存一组成员，成员通常可以增删 | 将当前查询结果误认为永久保留的历史数据 |
| 集合 / Snapshot | 集合用于组织数据；快照用于保留特定时刻的状态 | 无法复现某次实验使用的数据 |
| Ontology / 标签结果 | Ontology 规定类别、形状和属性；标签记录具体样本的答案 | 规范修改后难以解释旧标签 |
| Workflow / 计算 DAG | 工作流安排人员、审核与退回；计算 DAG 描述计算任务的依赖顺序 | 只按计算依赖设计，无法处理人工等待和修订 |

同名对象在不同平台中可能有不同规则，阅读时要关注其保存内容、可变性和对后续工作的影响。

## 对照同一条数据处理流程

| 阶段 | FiftyOne 开源版 | Voxel51 商业平台 | Encord |
| --- | --- | --- | --- |
| 接入 | SDK 导入与构造数据集 | 共享数据与企业连接，媒体访问独立配置 | 存储集成、注册引用与文件管理 |
| 观察 | 字段、视图、样本网格与 Panel | 同一分析基础叠加团队共享 | Explore 网格与分析面板 |
| 筛选交付 | View、标签及导出操作 | 沿用视图并结合快照与项目来源 | Collection → Dataset → Project 等路径 |
| 标注与 QA | 原生逐样本编辑、Schema 与标注集成 | Project / Batch / Task 与阶段审核 | Ontology、Workflow、角色与任务 |
| 版本边界 | 保存视图不等于冻结输入 | HEAD 与只读 Snapshot，外部资产需另管 | 标签分支、Checkpoint 与 Beta Label set versions |
| 自动处理 | SDK、Operator 与插件 | 委派任务、资源与服务管理 | Catalog / Custom Agent、阶段队列 |
| 评测反馈 | 评测结果与对象级视图 | 共享分析、版本与团队作业衔接 | 预测、质量分析、集合与任务动作 |

该表概括公开材料中的路径，不代表每项操作均已实测，也不把“通过集成完成”与“平台原生完整提供”混为一谈。

### 分析结果需要关联原始数据

三个平台都将原始内容、字段、标签、向量和评测结果关联到具体样本。用户看到异常指标后，需要打开对应图片、视频帧或对象，检查原因，再安排数据筛选或标签修订。共同的样本 ID 或对象引用，是这些操作得以衔接的基础。

### 工作入口影响导航与权限设计

FiftyOne 的分析围绕数据集与视图展开；Voxel51 在此基础上增加组织、项目和个人任务；Encord 的项目将数据、标签规范、流程和人员组合起来。导航和权限需要跟随这些对象设计，例如数据集访问权限与个人任务操作权限，就要分别处理。产品持续演进，具体关系应按文章记录的版本理解。

### 公开资料支持不同深度的架构分析

开源代码可以核对一个请求由哪些模块承接，但仍不能只读依赖就推导运行效果。商业平台的部署配置能确认一部分工作负载边界，SDK 能确认外部协议，却不能直接证明内部数据库分片、调度策略和事务设计。

因此，FiftyOne 篇结合源码解释请求处理过程；Voxel51 篇结合公开部署组件解释服务分工；Encord 篇重点解释数据流、任务状态和外部接口。商业后台未公开的数据库、调度与事务实现保留为未知。
